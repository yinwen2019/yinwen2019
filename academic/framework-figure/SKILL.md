# Framework Figure

准确表达当前论文的方法，并应用所选参考库中适用的视觉偏好。通过直接阅读小规模参考库工作，不建立类别目录、向量索引或检索服务。

## 选择参考库与使用边界

- `library_root` 是用户在自然语言中指定的库根目录，包含 `preferences.md` 与 `references/`。未指定时，使用本技能同目录下的 [preferences.md](preferences.md) 和 [references/](references/)。
- 使用现有库直接进入检索与设计，不先下载论文、不初始化库、不修改偏好，也不要求安装维护技能。其他用户可以直接复用默认库，或提供自己的库目录。
- 每次任务重新读取该根目录下的 `preferences.md` 和全部 `references/*/notes.md`，使用最新记录，不依赖聊天记忆或上次选图集合。未安装默认参考数据时说明库不可用，并按空库处理；不要自动创建它。
- 若用户要求新增、初始化或更新长期参考，使用独立的 `figure-library` 维护技能（可用时），完成后重新读取库。该技能不可用时，说明本次只读设计仍可继续；不把设计反馈默默写进共享库。
- 当前稿件及用户对其方法的澄清是科学事实依据；参考论文不能给当前方法添加不存在的模块、连接、损失、数据或结果。
- 视觉选择依次依据当前任务明确要求、所选库适用的已确认共性偏好、参考记录中的已确认局部偏好、本次临时设计判断。共享库的作者偏好作为借用风格依据，不改称当前用户已经确认的偏好。
- `framework`、`pipeline`、`architecture` 描述表达用途，可以组合，不作为分库或检索过滤条件。Intro 动机图、实验统计图和可编辑终稿不属于默认交付范围。

## 1. 理解当前方法

读取用户提供的背景与方法，梳理研究目的、输入与输出、核心模块、关键连接、训练与推理区别及需要突出的创新点。记录其在当前稿件或用户描述中的依据。

先确定模块和关系，再讨论视觉布局。若缺失信息会改变科学含义，例如支路是否共享参数、监督连接到哪里，提出聚焦问题；可以先整理已知部分，关键问题解决后再交付完整提示词。普通样式细节可作临时设计选择，无须逐项询问。

## 2. 全库查找与视觉核验

阅读全部简短记录，综合比较方法结构、表达目标和适用偏好，通常选择 2–4 张互补参考。结构与表达适配度优先，不因主题或会议等级相近就直接套用；不同领域的同类结构也可以借鉴。

打开候选图片核验，再按需补读来源论文。为每张入选图说明“借鉴什么、用于当前图的哪里、哪些内容不迁移”。参考风格冲突时按当前要求和已确认偏好取舍，不混合所有特征。

- 空库或库不可用：给出基于当前方法的临时设计，明确尚无个人图例依据，不将其记为已确认偏好。
- 仅一张：可以直接使用，说明参考依据有限，无须凑满数量。
- 无合适参考：根据当前方法重新组织布局，只应用仍适用的已确认偏好，说明未选用图例的原因。
- 图片缺失或无法查看：可以使用明确的文字反馈，但条目仅列为“文字参考依据（图片未核验）”，不分配图片附件编号，提示词不得声称存在对应附件。

## 3. 形成本文布局

用中文描述阅读顺序、分区、模块与连线、训练和推理如何呈现，以及创新点如何突出。阶段流程、并行分支、反馈循环、嵌套结构或总览加局部细节由方法本身决定。

将颜色、线型和形状赋予清楚且一致的含义。区分数据流、监督或损失连接、参数共享、可选步骤等实际存在的关系；不为美观添加关系。画布比例、面板数量、字体、配色和密度按任务与偏好决定，不固定复杂度或为充实版面新增内容。

设计说明区分当前论文事实、参考库偏好、参考图启发和临时选择，使主要视觉决策可追溯，无须给每个间距添加出处。

## 4. 默认交付

1. **中文设计说明**：方法要点、整体布局、模块连接、创新点表现及参考选择理由。
2. **参考图片列表**：仅对已实际查看且可提供给生图工具的图片，按 `Reference 1`、`Reference 2` 等列出实际文件路径或可访问图片链接、论文来源与借鉴范围。编号与提示词一致。仅有文字记录时另列文字依据；没有可用图片时明确说明没有图片附件。
3. **完整英文生图提示词**：可独立复制使用，包含本文任务、准确的英文模块标签、分区与阅读顺序、关键连接及箭头语义、视觉层级、配色与排版要求、每张附件的借鉴范围。参考图用于视觉表达，科学内容与标签以当前方法为准。外部工具需要接收列出的图片附件，仅复制文字或本地路径不会自动传入图像。

最终提示词不留下未解决的关键方法占位符。检查标签、公式和数字有依据，训练与推理未混淆，箭头方向及分支一致，当前论文术语或结构没有被参考论文替换。生成结果仍需核对文字与连线；提示词不能保证外部模型必然正确执行。

初版到上述交付为止。直接调用生图 API 或制作可编辑终稿由用户另行提出对应任务。

## 5. 反馈与继续使用

反馈先修改本次方案和提示词。本技能保持参考库只读；用户明确要求将反馈用于长期偏好时，交由 `figure-library` 在指定库内更新，再重新读取。不要将某次选图集合固定成永久模板。

参考库扩大到全库阅读明显影响效率时，再讨论新的组织方式；当前保持全库阅读与逐图核验。
