# Framework Figure

将当前论文的方法表达清楚，并应用用户已经确认的视觉偏好。初版通过直接阅读小规模参考库工作，不建立类别目录、向量索引、检索服务或自动抓取流程。

## 入口与事实来源

- 用户要求收藏图例、补充论文上下文或更新偏好时，执行“维护参考库”。要求为当前文章设计主框架图时，执行“设计与提示词”。同一次请求可以涉及两者。
- 每次任务重新读取 [preferences.md](preferences.md) 及 [references/](references/) 下全部 `*/notes.md`，使用最新记录，不依赖聊天记忆或上次选图结果。
- 当前论文、公式、方法描述及用户对它们的澄清是科学内容的依据。参考论文提供可借鉴的表达方式，不能给当前方法添加不存在的模块、连接、损失、数据或结果。
- 视觉选择依次依据：当前任务明确要求、适用的已确认共性偏好、参考记录中的已确认局部偏好、临时设计判断。始终保持科学含义准确。
- `framework`、`pipeline`、`architecture` 仅是表达用途，可以组合，不作为分库或检索过滤条件。
- 当前稿件默认只作为本次任务输入。仅将用户指定收录为长期参考的材料保存到参考库。保存与远程同步遵循当前任务已经授权的范围，并如实报告完成状态。

## 维护参考库

每张图使用一个稳定目录 `references/<reference-id>/`，其中保存原始参考图片和 `notes.md`。优先使用简短论文名加图号命名；信息不足时使用未占用的 `ref-0001` 等编号。补齐来源时保留原编号，避免已有引用失效。同篇论文不同图分别建记录，同一图的补充反馈更新原记录。

入库时先查看图片；按用户提供的论文、图注或公开来源补充方法上下文。找不到的信息写“未知”，标明仅有图片、图注或全文等证据范围。不能从图像风格推断论文贡献，不能把图片中无法辨认的文字当作已核实标签。

`notes.md` 使用以下简短记录结构；按实际内容填写，未知项可以留待后续补充：

```markdown
# <reference-id> · <简短标题>

## 来源
- 论文标题、原文链接、图号：
- 图片文件：<同目录内的实际文件名>
- 上下文依据：<用户描述 / 图注 / 论文章节或页码>
- 最近更新：<实际日期>

## 科学上下文
- 研究问题与动机：
- 方法概要与关键模块关系：
- 本图表达范围：<整体方法 / 阶段流程 / 内部结构，可组合>

## 视觉分析
- 布局与阅读顺序、分组和嵌套：
- 模块连接与箭头含义：
- 配色、字体、线型与信息层级：
- 可迁移的表达方式及适用条件：

## 用户偏好
- 已确认：<喜欢 / 不喜欢；注明针对整图还是局部，记录简短原话或忠实转述与日期>
- 待确认：<AI 提出的偏好假设及观察依据>
- 不宜迁移：<仅适用于该论文的结构或内容>

## 待补充
- <缺失来源、方法信息或尚不明确的反馈；没有则写“无”>
```

没有图片时可以先保存上下文记录，但标注“图片待补充”；选图时不能宣称已分析其视觉细节。只有图像而没有论文时，可以分析可见布局，科学上下文保持未知或仅记录用户明确提供的内容。

每次入库或修订后检查共性偏好：

- 用户明确说明适用于后续绘图的偏好，可以直接写入 `preferences.md` 的已确认部分。
- 同一倾向在多个独立参考的已确认反馈中反复出现时，可以归纳为共性规则，并链接支持记录、注明适用条件。仅在图片中重复观察到某种样式，仍属于待确认推断。
- 一次具体图的偏好先记在该图中；“这次用蓝色”等任务限定指令仅作用于本次设计。
- 用户纠正旧偏好时，修订对应记录及其共性规则，保留简短变更原因；避免互相冲突的规则同时处于有效状态。无法判断新反馈是局部还是全局时，先按局部处理，需要影响当前设计时再澄清。
- 简要说明新增了哪条参考、补充了哪些信息、哪些共性偏好发生了变化。没有新偏好证据时，不为填充文件而新增规则。

## 设计与提示词

### 1. 理解当前方法

读取用户提供的背景与方法，梳理研究目的、输入与输出、核心模块、关键连接、训练与推理区别、需要突出的一到两个创新点。标明内容在当前稿件或用户描述中的依据。

先确定模块和关系，再讨论视觉布局。若缺失信息会改变科学含义，例如支路是否共享参数、监督连接到哪里，提出聚焦问题；可以先整理已知部分，待关键问题解决后再交付完整提示词。普通样式细节可作临时设计选择，并说明依据，无须逐项询问。

### 2. 全库查找与视觉核验

读取全部简短记录，综合比较方法结构、表达目标和用户偏好，通常选择 2–4 张互补参考。优先考虑结构与表达适配度，不因主题、会议等级相似就直接套用；不同领域的同类结构同样可以借鉴。

打开候选图片核验，再按需补读论文。为每张入选图说明“借鉴什么、用于当前图的哪里、哪些内容不迁移”。参考图之间风格冲突时，按当前要求和已确认偏好取舍，不把所有特征混合。

- 空库：给出基于当前方法的临时设计，明确尚无个人图例依据；不把这些选择记为已确认偏好。
- 仅一张：可以直接使用，说明参考依据有限，无须凑满数量。
- 无合适参考：根据当前方法重新组织布局，只使用仍然适用的已确认偏好，并说明未选用图例的原因。
- 图片缺失或无法查看：说明限制；可以使用明确的文字反馈，不能把未查看的图片作为已经视觉核验的依据。此类条目仅列为“文字参考依据（图片未核验）”，不分配图片附件编号，提示词不得声称存在对应附件。

### 3. 形成本文布局

用中文描述整体阅读顺序、分区、模块与连线、训练和推理的呈现方式，以及创新点如何突出。布局可以是阶段式、并行分支、反馈循环、嵌套结构或总览加局部细节，由方法本身决定。

将颜色、线型和形状赋予清楚且一致的含义。区分数据流、监督或损失连接、参数共享、可选步骤等实际存在的关系；不为美观添加关系。布局尺寸、面板数量、字体、颜色和密度均根据当前任务与偏好决定，不固定画布或为了充实版面添加内容。

设计说明中区分当前论文事实、用户偏好、参考图启发和本次临时选择。让读者能够追溯主要视觉决策，但无需给每个细小间距添加出处。

### 4. 默认交付

按以下顺序输出：

1. **中文设计说明**：方法要点、整体布局、模块连接、创新点表现及参考选择理由。
2. **参考图列表**：仅对已实际查看且可提供给生图工具的图片，按 `Reference 1`、`Reference 2` 等列出实际文件路径或可访问图片链接、论文来源，以及每张图的借鉴范围。编号与提示词一致；仅使用文字记录时另列文字依据，空库或没有可用图片时明确说明没有图片附件。
3. **完整英文生图提示词**：可独立复制使用，包含本文任务、准确的英文模块标签、分区与阅读顺序、全部关键连接及箭头含义、视觉层级、配色和排版要求，以及每张附件的借鉴范围。明确参考图用于视觉表达，论文内容与标签以当前方法为准。外部生图工具需要接收列出的图片附件，仅复制文字或本地路径不会自动传入图像。

最终提示词不得留下未解决的关键方法占位符。检查标签、公式和数字均有依据，训练与推理未混淆，箭头方向及分支关系一致；保证目标论文内容没有被参考论文的术语或结构替换。提示词可以要求清晰文字与准确连线，但不能承诺外部模型一定正确完成，生成结果仍需核对。

初版到上述交付为止。直接调用生图 API 或制作可编辑终稿需要用户另行提出对应任务。

### 5. 反馈与后续使用

反馈先用于修改本次设计和提示词。涉及长期喜好的内容，再按“维护参考库”更新相应文件，说明哪些是本次调整、哪些已成为后续默认。

参考库扩大后，只有在全库阅读实际影响效率时，再与用户讨论新的组织方式。每次使用仍以最新文件为准，不能把某次选图集合固定成永久模板。
