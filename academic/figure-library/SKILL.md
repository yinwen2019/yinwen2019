# Figure Library

维护一个小规模、可持续更新的参考库，服务于 framework、pipeline 和 architecture 方法图。图的表达用途可以组合，不建立类别目录或检索服务。

## 选择参考库

- `library_root` 是自然语言指定的库根目录，包含 `preferences.md` 和 `references/`，不要求配置文件或数据库。
- 优先使用用户明确指定的根目录。维护本仓库已有库时，默认根目录为本技能旁的 `../framework-figure/`；数据继续保存在原位置。
- 用户直接复用现有库时，读取即可，无需初始化或更新。现有库的作者偏好保留原归属，不能改写成当前使用者已经确认的偏好。
- 为另一位用户创建个人库时，使用其明确指定的独立目录。目的地未明确时，先确定目标目录，再写入；不要覆盖原作者的默认库。可以先准备论文分析。
- 初始化只补充缺少的目录和文件，保留已有内容。首个参考到来即可使用。没有参考图时，保持空库，不制造样例或预设审美。

新的 `preferences.md` 可采用以下最小结构：

```markdown
# 个人框架图偏好
归属：<用户明确提供的名称或“未指定”>

## 已确认的共性偏好
尚无。后续仅依据用户明确反馈逐步积累。

## 待确认的偏好假设
尚无。视觉观察不自动成为用户偏好。

## 修订说明
记录实际更新日期、变化和原因。
```

## 从论文链接到参考记录

1. **接收与核对来源**：保存用户原始链接；可以清除复制产生的尾部空格或 `.pdf` 后多余句号，但记录修正后的地址。下载到临时缓存，确认响应确实为可打开的 PDF，核对标题、作者及会议信息。奖项或 Oral 等信息若仅由用户提供，应注明来源，不当作已核实事实。使用替代版本时核对论文身份，记录实际下载来源和版本。
2. **定位主框架图**：阅读摘要、引言中的问题与动机、方法部分及图注。选择最完整表达方法模块和关系的图，不能机械地选 Figure 1。整体框架与局部架构分散在多图时，可以分别入库，并说明各自范围。
3. **查看完整页面**：渲染候选页，核对图号、子图标签、图例、文字和连接。由执行者通过视觉检查确定裁剪框；只有存在无法判断的目标图歧义时才询问用户。
4. **高清截取**：调用本技能的 [scripts/extract_figure.py](scripts/extract_figure.py)，默认 400 DPI、JPEG 质量 95。裁图覆盖完整图形、内部标签和图例，保留少量边距，避免混入正文或截断边缘。源 PDF 继续留在临时缓存，不将整篇论文加入参考库。
5. **检查最终 JPG**：打开导出的图片，检查是否清晰、完整、方向正确且没有正文残留。低分辨率原始位图不会因提高 DPI 获得真实细节；如有此限制应记录。必要时调整裁剪框后重新渲染。
6. **写入上下文与分析**：将图片和 `notes.md` 放入同一参考目录，分别记录论文事实、视觉观察和用户偏好。方法摘要用自己的话概述，注明章节、页码和图注依据。
7. **更新偏好并报告**：检查是否存在新的共性偏好证据，报告新建或更新的参考、实际文件路径、质量检查结果及仍缺少的信息。按当前任务已授权范围保存和同步；本技能不自动获得额外发布权限。

裁图命令（PDF 页码从 1 开始，坐标为页面左上角原点的 PDF points）：

```bash
python scripts/extract_figure.py PAPER.pdf --page N --bbox X0 Y0 X1 Y1 --output figure.jpg --dpi 400 --quality 95
```

使用本技能目录下的实际脚本路径。脚本输出的 JSON 元信息用于填入记录；脚本通过校验不等于已经完成视觉检查。

脚本依赖 Python 与 `PyMuPDF>=1.22`；缺失时使用当前环境允许的临时或项目环境安装。`PAPER.pdf` 也可以替换为公开 PDF URL。脚本不会自动选择图或裁剪框；先完成整页查看再提供坐标。输出已存在时默认拒绝覆盖，确认更新同一记录且检查过新裁图后才使用 `--overwrite`。遇到 HTTP 拒绝或非 PDF 响应，使用可访问的正式来源或用户提供的本地 PDF，并记录实际来源。

## 记录格式与重复入库

每张图保存为 `references/<reference-id>/figure.jpg` 和 `notes.md`。优先以论文短名和图号命名；来源未知时使用未占用的 `ref-0001` 等编号，后续补齐来源仍保留编号。

入库前查找现有记录：同一论文来源和图号更新原条目，保留原有用户反馈；同篇不同图分别存放。同一论文的替代版本需核对图的内容，不能仅因下载 URL 不同就重复建条目，也不能误覆盖另一图。修改已存在图片前先在临时文件中完成裁图检查。

`notes.md` 使用以下简短结构；不确定内容写“未知”，明确证据范围：

```markdown
# <reference-id> · <论文短名 / 图号>

## 来源与截取
- 论文标题、作者、会议：
- 用户原始 URL：
- 实际下载 URL / 版本：
- 图号与 PDF 页码（从 1 开始）：
- 图片：figure.jpg
- 裁剪框：[x0, y0, x1, y1]，单位 points，页面左上角为原点
- 渲染：<工具与版本>；<DPI>；JPEG 质量：<值>；尺寸：<宽 × 高 px>
- 源 PDF SHA256：
- 上下文依据：<章节、PDF 页码、图注或用户描述>
- 最近更新：<实际日期>
- 图片检查：<已查看最终 JPG 的结论或明确限制>

## 科学上下文
- 研究问题与动机：
- 方法概要与关键模块关系：
- 本图表达范围：

## 视觉分析
- 布局、阅读顺序、分组和嵌套：
- 模块连接与箭头语义：
- 配色、字体、线型和信息层级：
- 可迁移的表达方式与适用条件：

## 用户偏好
- 已确认：<用户原话或忠实转述、日期、针对整图或局部>
- 待确认：<AI 的偏好假设及观察依据>
- 不宜迁移：<该论文专属的科学结构、术语或内容>

## 待补充
- <未知项；没有则写“无”>
```

直接提供图片时，保存用户提供的原图；可按需转成 JPG，但保留其原始尺寸，不虚构 PDF 页码、裁剪框或哈希。相应字段写“不适用”或“未知”。没有图片时可以先建文字记录并标注“图片待补充”；下载被拒绝或无法定位图形时报告具体阻碍，不能用其他图片冒充成功。

## 更新偏好

- “这是我喜欢的论文/图”只确认该对象被选为正向参考；具体配色、字体和布局偏好仍需用户反馈。不能把论文获奖或被选中解释为喜欢每个视觉细节。
- 用户明确指定长期适用的偏好，可以写入 `preferences.md` 的已确认部分。多个参考中反复出现的已确认反馈，也可归纳为有条件的共性规则，链接支持记录。
- AI 从图片中观察到的共同样式写入待确认部分，不自动升级为用户喜好；单图局部偏好保留在该图记录中。
- “这次用蓝色”等临时指令仅作用于当前设计。新反馈的长期范围不明确时先按局部处理。
- 用户纠正旧偏好时更新有效规则及相关记录，简短记录日期、变化和原因，避免冲突规则同时生效。没有新增证据时不为填充内容而增加偏好。

完成入库后即可由任意绘图工作流读取该库；维护技能本身不依赖安装 `framework-figure`，也不调用生图 API。
